# Write Website Copy

Read [references/voice-profile.md](references/voice-profile.md) completely before writing or approving copy.

## Work Interface First

1. Identify the page's job and the reader's next useful action.
2. Let hierarchy, layout, controls, charts, and labels explain the product.
3. Remove text that repeats visible information.
4. Write literal labels, compact curious headings, and understated actions.
5. Add body copy only when the interface cannot carry the meaning.
6. Move academic and technical depth into progressive methodology or FAQ layers.
7. Audit every text node against the house voice before shipping.

Do not add explanatory sections merely to make a page feel complete. A section must contribute information the reader cannot already see.

## Write The Product Voice

- Sound analytic, young, conversational, and formal enough.
- Speak as the product. Use the brand name by default and Koi for authored observations.
- Assume basic League of Legends and betting familiarity.
- Assume no mathematical or statistical training.
- Prefer a clear opinion over a perfectly balanced summary.
- Keep uncertainty proportional to how breakable the claim is.
- Prefer `suggests`, then `is associated with`, then `indicates`.
- Use humor, metaphors, and rhetorical questions when they sharpen the idea.
- Never let playfulness carry the factual meaning alone.

## Shape The Copy

- Use compact fragments and Title Case for headings.
- Make headlines as short as the idea permits.
- Keep section introductions within roughly 1.5 rendered lines.
- Default to two sentences per paragraph.
- Use literal metric labels.
- Make chart titles takeaway driven and playful when the evidence supports it.
- Use chart subtitles for the finding, not provenance or methodology.
- Use distinctive navigation labels that remain understandable.
- Use understated links for actions.
- Keep mobile copy identical to desktop copy.
- Explain unavailable states briefly. Add recovery guidance only when a recovery exists.
- Summarize status implications instead of narrating internal events.

## Control Technical Depth

- Keep primary surfaces intuitive and low complexity.
- Put academic and technical material in methodology or FAQ disclosures.
- Use analogies before formulas when they preserve accuracy.
- Use LaTeX only when a formula is essential.
- Never expose internal model, function, module, pipeline, or implementation names.
- Put material uncertainty and limitations in footnotes using superscript references such as `^1` and `^2`.
- Never invent specificity, provenance, certainty, selections, outcomes, or explanations.

## Format Consistently

- Use dates as `DD-MM-YYYY`.
- Use decimal points.
- Use `%`, not percentage points or `pp`.
- Use numerals.
- Use familiar abbreviations such as WR, ROI, and P/L when the surrounding copy stays simple.
- Do not use semicolons.
- Do not use em dashes.

## Final Copy Gate

Before shipping, confirm:

- Every sentence earns its space.
- The interface carries more explanation than the prose.
- The opening does not summarize what the page visibly shows.
- No paragraph exists only to transition into the next section.
- The writing contains a real point of view.
- Sentence lengths and rhythms vary naturally.
- The copy avoids the prohibited AI-writing patterns in the voice profile.
- Claims remain evidence-bounded.
- Dates, numbers, abbreviations, punctuation, and footnotes follow the profile.
- Mobile and desktop use the same copy.

If the copy fails any item, revise it before implementation or approval.
